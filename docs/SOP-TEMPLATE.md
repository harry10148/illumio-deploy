# SOP 模板

`docs/{pce,ven,cert,platform}/*.md` 都必須依本模板撰寫。新增 SOP 時複製下方「模板本體」，改名後填入內容。`reference/` 下的參考資料不受此限。

## 規則

1. 第一行是 H1 標題，接著是「適用版本」與「最後更新」兩行。
2. §1 到 §7 的章節標題與順序不得更動；沒有內容的章節寫「— 無 —」。
3. 指令一律放在 fenced code block，並標示語言（`bash`、`powershell`、`cmd`、`yaml`）。
4. 不寫入真實的啟用碼、密碼、API 金鑰、私鑰。主機名稱與 IP 用範例值（`example.com`、`10.0.0.x`）或 `<PLACEHOLDER>` 形式的佔位符。
5. §3 的指令若修正過錯誤、做過去識別，或與原始 SOP 不同，必須在 §7 記錄改了什麼與日期。
6. §6 每一條來源標示 `[NotebookLM]`、`[Web]` 或 `[現場]`。
7. §7 若沒有差異，保留章節標題並寫「驗證結果與原廠一致」。沒有實機驗證過的內容也寫在這裡。
8. 一個主題只寫在一份文件裡，其他地方用連結。

提交前執行 `./scripts/check-docs.sh`，它會檢查規則 1、2、4（啟用碼形式的字串）與所有相對連結。

## 模板本體

```markdown
# <SOP 標題>

> **適用版本**：Illumio PCE 25.x / VEN 25.x（依驗證結果填）  
> **最後更新**：YYYY-MM-DD

## 1. 目的與適用情境

一兩句話說明這份 SOP 解決什麼問題、什麼時候用。

## 2. 前置條件

- 權限：…
- 工具：…
- 網路與防火牆：…

## 3. 操作步驟

    ```bash
    sudo illumio-pce-ctl status
    ```

## 4. 驗證

- 觀察點 1：…

## 5. 失敗回滾 / 救援

步驟失敗時怎麼處理、怎麼退回。

## 6. 原廠文件參照

- [NotebookLM] `Install, Configure, and Upgrade Guide 25.4` §章節名稱
- [Web] https://docs.illumio.com/…
- [現場] YYYY-MM-DD 於 <環境> 實測

## 7. 與原廠差異（若有）

- 步驟 N：本 SOP 用 `…`，原廠為 `…`，原因是 …
```
